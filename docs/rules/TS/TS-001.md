# Rule ID

TS-001

---

# Rule Name

Primary Target Zone (PTZ) Selection

---

# Status

Approved

---

# Purpose

Identify the single Daily Fair Value Gap (FVG) that becomes the Primary Target Zone (PTZ).

The PTZ is the only Daily FVG used as the starting point for Recursive Manipulation Refinement.

TS-001 is a pure selection rule. It performs one evaluation per invocation and returns a selection result. It does not manage the lifecycle of the PTZ it returns.

---

# Inputs

- Daily OHLC candles
- Current Market Price
- Excluded FVG Set

Notes:

Current Market Price is used only for distance calculation.

Touch detection is performed only on completed Daily candles by TM-001.

Current Market Price is used only for distance calculation.

Touch detection is performed only on completed Daily candles by TM-001.

---

## Excluded FVG Set

A set of Daily FVG identifiers supplied by the caller that shall not be considered during selection.

In the current architecture, the Daily FVG identifier is the Candle C timestamp produced by DR-001.

The set is supplied by the caller on each invocation.

The set is opaque to TS-001. TS-001 shall not interpret, infer or act upon the reason an FVG appears in this set.

The set may be empty.

An identifier that does not correspond to any detected FVG has no effect.

The current identifier (Candle C timestamp) is valid because DR-001 produces at most one FVG per Candle C. The Bullish condition Low(C) > High(A) and the Bearish condition High(C) < Low(A) are mutually exclusive for a given three-candle sequence.

---

# Statelessness

TS-001 performs exactly one evaluation per invocation.

TS-001 retains no state between invocations.

Two invocations supplied with identical inputs shall produce an identical result.

Invocation timing, re-invocation policy, PTZ lifetime, PTZ completion and the construction and persistence of the Excluded FVG Set are owned by the orchestration layer.

---

# Daily Candle Convention

The Daily candle boundary and timezone convention—including the timestamp carried by a Daily candle, the time at which a Daily candle is considered completed, and the mapping of a Daily candle to a calendar day—is defined by DS-001 (Market Data Specification) and is not restated here.

TS-001 applies the conventions defined in DS-001 when determining:

- the latest completed Daily candle (the anchor)
- whether a Candle C falls inside the lookback window

---

# Configuration

## Lookback Period

Default:

LOOKBACK_DAYS (defined in CFG-001)

The lookback window is anchored to the latest completed Daily candle.

The anchor candle is included in the window.

The window spans exactly LOOKBACK_DAYS calendar days counting backwards from the anchor, weekends included.

A Daily FVG belongs to the window only if its third candle (Candle C) falls inside the window.

Candles A and B may fall outside the window.

---

# Definitions

## Valid Daily FVG

A valid Daily Fair Value Gap consists of a three-candle imbalance where the aggressive middle candle creates an untraded gap between Candle 1 and Candle 3.

The exact mathematical definition is specified in DR-001.

---

## Untested Daily FVG

Touch detection is owned by TM-001.

TS-001 consumes the TouchStatus classification produced by TM-001.

A Daily Fair Value Gap is eligible for PTZ selection only if its TouchStatus is UNTESTED.

---

# Selection Algorithm

## Step 1

Detect all valid Daily FVGs using DR-001.

Bullish and Bearish FVGs form a single candidate pool.

## Step 2

Anchor to the latest completed Daily candle.

Scan exactly LOOKBACK_DAYS calendar days counting backwards from the anchor.

The anchor candle is included in the window.

Retain only those Daily FVGs whose third candle (Candle C) falls inside this window.

## Step 3

Remove every FVG whose identifier appears in the Excluded FVG Set.

## Step 4

Obtain the TouchStatus classification for each remaining candidate from TM-001.

Remove every FVG whose TouchStatus is TESTED.

## Step 5

For each remaining FVG, calculate the distance from the current market price to its nearest boundary.

Never use the midpoint or the far boundary.

## Step 6

Select the FVG with the smallest nearest-boundary distance.

Direction does not influence ranking.

If two FVGs are equally near, select the newest one using the later Candle C timestamp.

## Step 7

Return the selected Daily FVG as the Primary Target Zone (PTZ).

Each invocation of TS-001 returns at most one Primary Target Zone.

---

## Ordering Constraints

Step 1 shall precede Step 2. Filtering is applied to a detected candidate pool.

Step 3 and Step 4 shall both precede Step 5. No distance is calculated for any FVG that is excluded or TESTED.

Step 3 and Step 4 are order-independent with respect to the result and may be reordered by an implementation without changing behaviour.

---

# Output

Exactly one Primary Target Zone (PTZ).

or

No PTZ Found.

No PTZ Found is returned when the candidate pool is empty after Step 4.

---

# Acceptance Criteria

✓ Detects candidates using DR-001 before applying any filter.

✓ Anchors the window to the latest completed Daily candle.

✓ Includes the anchor candle in the window.

✓ Uses exactly LOOKBACK_DAYS calendar days as defined by CFG-001.

✓ Includes an FVG in the window only if its Candle C falls inside the window.

✓ Removes every FVG whose identifier appears in the Excluded FVG Set before calculating any distance.

✓ Consumes the TouchStatus classification produced by TM-001 and removes every TESTED FVG before calculating any distance.

✓ Ranks a single pool of Bullish and Bearish FVGs by distance to the nearest boundary.

✓ Breaks distance ties by choosing the newest FVG using the later Candle C timestamp.

✓ Returns at most one PTZ per invocation, or No PTZ Found.

✓ Retains no state between invocations and returns an identical result for identical inputs.

---

# Rule Responsibilities

✓ Filter Daily FVGs by the lookback window.

✓ Apply the supplied Excluded FVG Set.

✓ Apply the TouchStatus classification supplied by TM-001.

✓ Calculate nearest-boundary distance.

✓ Select the Primary Target Zone.

---

# Rule Limitations

Does not:

- Detect FVGs.
- Determine TouchStatus.
- Decide when it is invoked.
- Retain state between invocations.
- Manage PTZ lifetime or PTZ completion.
- Construct or persist the Excluded FVG Set.
- Interpret why an FVG is excluded.
- Analyse lower timeframes.
- Detect, monitor or consume Points of Interest.
- Execute trades.
- Manage trades.
